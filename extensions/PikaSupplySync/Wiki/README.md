# 货源同步（PikaSupplySync）

本说明对应 PikaSupplySync `1.1.17` 与 PikaCatalogHub `0.6.9`。继承明确零库存与目录缺项分开保护、普通目录缺失/null 库存拒绝；本版增加目录／详情／图片的有界请求、尝试及预算诊断，不改变原批量、游标、重试或写入保护，不增加配置、持久状态或第二引擎。basic 精简目录、v1/v2 data、六项周期选择、分类图和默认关闭的完整配置跟随策略保持。分类图维护使用独立受信 CLI 和精确回执，不重入库，详见[分类图维护说明](../../PikaCatalogHub/Wiki/README.md#分类图与受信维护入口)。本扩展不依赖官方商店或 `_plugin_start`。当前候选及证据边界见[项目状态](../../../docs/PROJECT_STATUS.md)；[新手图文](../../../docs/USER_GUIDE.md)和[验收清单](../../../docs/CATALOG_WORKFLOW_ACCEPTANCE.md)不代表目标站已经验收。

首次分类方式由 CatalogHub 冻结并确认，默认 `smart`，`mirror` 必须明确选择。定向入口自执行端 Supply `1.1.15` 提供；已具备当前目录／图标协议能力的源端不因此强制升级。源端仍须按安装流程维护 registry 并启用提供相应能力的 PikaCatalogHub，实际能力每次严格校验，不另作最低版本兼容承诺；不要求源站改变已有分类设置或为导出目录启动周期同步。已有映射的来源不能换模式。SupplySync 不新增、改名、移动、删除或重排分类，也不会把完整商品配置跟随扩大为分类树同步。配套要求和配对恢复边界见[智能货源中心说明](../../PikaCatalogHub/Wiki/README.md#首次分类方式)与[镜像升级与回退](../../PikaCatalogHub/Wiki/README.md#7-镜像升级与回退)。

## basic 精简目录与目录失败

只有 `basic`、协议 `0` 且已有 mirror 分类映射的货源使用精简目录；普通货源与其他模式继续原目录路径。映射不是永久能力证明：每次都要通过当前 schema2 能力声明、签名认证、完整结构、分类父链与数量校验，失败停止本货源，不回退到 legacy 目录。合法缺项与明确零库存按下述各自保护门处理；目录不能凭本地历史商品清单强制补齐，也不读取旧任务 fingerprint 充当能力开关。

精简目录仅提供 code/category_id/stock 排批；名称、图片、说明、价格、库存、规格继续逐件读取详情，并保留换汇、既有加价、游标、公平性、商品级开关和写前身份门。它不创建商品或改分类，不需要重新接入或重新入库。目录、快照、图片和执行预算的原安全上限均不变。

目录失败时，本货源尚未执行商品写入；多货源中其他来源可能已完成自己的批次。后台仅展示安全类别、HTTP 状态、cURL 码、耗时与尝试次数，不展示响应正文、上游地址或密钥。`response_size` 表示目录超过 16 MiB 安全上限，缩小同步批量不能减小整份目录；HTTP 200 只表示观测到该状态，不代表响应完整、JSON 合法或同步成功。旧记录无诊断时不补造。刷新运行记录仍为只读，不重新同步。

## 周期同步字段与历史记录

后台「本地扩展 → 货源同步」提供名称、图片、说明、价格、库存、规格六个独立勾选项。已明确保存后，未勾选项保留本地；全部不选时不请求上游、不写任何商品字段（包括内部同步标记）。要保护自行编辑的图文，可只勾选价格、库存、规格；全勾选则在原生单品开关与安全门允许范围内跟随上游。`basic` 仍只更新既有受管商品，不创建商品、不迁移分类或改变分类图。

旧配置六键全部缺失时继续原旧规则。页面全勾仅是“待保存选择”，首次完整保存才切换到新语义；不能把旧配置视为已经全选。兼容差异特别包括：旧规则的配置同步开启、价格同步关闭仍可能更新配置中的 SKU 价格。旧客户端省略六键不会将已保存选择重置；部分六键或非法值会整体拒绝，其他配置不落盘。

新选择还与原生单品开关取交集：图文与规格结构受「配置同步」控制；价格（包括精确匹配的既有规格价格）受「价格同步」控制；库存受「库存同步」控制。库存未勾选也不执行缺货清零／优先清零；图片未勾选不下载周期同步封面。智能货源中心首次入库仍采用既有完整字段与已确认加价，不受这些周期选择替代。

规格开启而价格关闭时，新增、删除、改名、映射变化或缺少精确价格身份会保留该商品完整原规格配置，提示“规格或价格变更待确认”，其他独立已选字段继续。价格开启而规格关闭时，仅更新已有精确匹配价格，不增删或改名规格；不匹配部分保留并提示。未知配置段默认保留本地；未知段差异时，已知配置及其他独立已选字段仍可能更新，`widget/draft_status` 保留本地，不代表整件商品冻结。提示沿用部分处理结果，不创建永久商品状态、上架控制或自动补查任务。

### 完整商品配置跟随上游（默认关闭）

勾选后，上游变更／删除将覆盖所选货源受管商品 `config` 中的本地手工修改；仅在价格和规格同步双有效，并通过单品开关与既有安全校验时执行。关闭任一项会暂停完整跟随，但不会取消此选择。名称、图片、说明、库存仍各守原选择，分类和首次入库规则不变。

- 「参与同步的货源」（`source_ids`）继续控制原同步集合，留空仍为全部；「完整配置跟随的货源」（`follow_upstream_config_source_ids`）是独立名单，启用时必须明确填写，空或缺键不代表全部，也不从前者推定。两处都使用英文逗号分隔的正整数共享店铺 ID。只想让其中一个货源完整跟随时，保留原参与同步设置，仅把目标货源填入独立跟随名单；其他货源仍正常同步并沿用默认未知配置保护。
- 完整跟随只对同时属于本次同步范围和明确跟随名单的来源生效。跟随名单不会启动未参与同步的货源；CLI 的 `--source` 或同步范围扩张也不会扩大跟随归属。六项选择必须完整保存，但价格或规格可以暂时关闭，此时完整跟随不生效，原保护保持。当前页面全勾、旧配置缺键和 legacy 规则都不会自动启用该策略。
- 合法的整份配置沿原 `SharedGateway → SharedCurrency → PriceAdjuster` 链规范化，已知金额只按原规则换汇、加价；其余节点按进入配置投影层的结构与值跟随增改删，不额外把数字当金额。对投影层未知的节点仍可能被原生换汇识别，不能再次换汇或加价。配置和匹配的 `widget/draft_status` 同事务保存；原始顶层结构、已知价格或映射非法时，本件零写退出。
- 旧客户端省略新选择不会首次启用它；已经启用时，省略该选择不能扩张独立跟随名单。旧配置即使保存了开关，也不能仅凭原同步名单自动建立完整归属，必须明确填写独立跟随名单或关闭策略。不要通过删除六项配置或直接运行官方整商品同步绕过保护。
- 关闭选择只停止以后完整覆盖，不会找回已经覆盖／删除的本地手工配置。代码回退也不等于数据恢复；生产启用、同步和数据恢复须另行批准并准备相应备份。

「同步运行记录」只读已有日志及每源历史状态，分别展示实际模式记录、预演、类型未记录的旧日志和最近持久化批次；旧状态时区未记录，不强行判断它与日志的先后。保存次数不是字段变化数；零动作、部分处理、失败和规格待确认均单独提示。「刷新记录」不触发同步、不保存配置，并保留尚未保存的勾选。Web 无法验证 timer 或当前进程，始终标“未核实”；扩展开关和历史成功都不是当前运行证明。

本轮日志与最近持久化 state 可能不是同一轮：目录前置失败尚未进入动作阶段时，state 可仍对应上一次到达动作阶段的运行。应分别核对各自时间与阶段，不把旧 state 当作本轮成功或本轮无动作的证据。每源 `request_diagnostics` 按 `catalog/detail/image` 保存 `count`、`last`、`last_failure`，每个逻辑请求的 `attempt_history` 最多 3 次，仅含有界枚举和数值；预算数值是最近既有预算检查的采样，不是日志落笔时的实时读钟，未采集字段省略，不是测量为零或完整商品级追踪。

这些请求观察只覆盖 HTTP／JSON 边界，`none` 不代表后续业务校验、图片解码或数据库提交成功；实际来源结果仍以同轮 `status/applied/failed/cover_failed` 为准。`phase` 区分前置、目录、规划和动作阶段；无请求诊断的动作间预算耗尽不推定为某个详情或图片失败。新增诊断在现有 CLI 结果与日志中保留，后台继续展示原有来源结果和独立历史 state，不展示新嵌套字段。

### 受控定向验证（临时 CLI 参数）

原生 `bin/sync.php` 的 `--only-code-hashes=HASH[,HASH]` 仅接受1–2个互不相同的小写12位十六进制值，即既有上游 code 的 SHA256 前12位；必须同时明确一个 `--source`。目标须在完整本地受管集合及本次完整目录中各唯一匹配、库存为正。先核全来源清零熔断，不靠过滤目标绕过安全门；非受管、缺项、碰撞或单品价格／配置／库存开关不允许时，在详情前停止。哈希不是授权凭据，真实 code 和配置值不应放进公开报告。

保存配置必须启用扩展、保持 basic、六项全选、明确允许目标来源完整跟随，批量上限至少覆盖目标数。每次详情前及事务锁内重新读取保存配置：命令行不能重新扩大已收窄的参与来源、模式、字段或完整跟随名单，批量取保存上限与原请求上限的较小值；并重新核商品身份及既有加价。普通无定向参数的 CLI 覆盖语义不变。本入口不是后台设置、定时器配置或一次物理请求诊断器。

合法整份 config 沿原换汇和商品既有加价链覆盖本地增改删，已设置20%的商品仍用20%，不使用新品默认加价代替，也不在重复同步时重复加价。未被既有规则识别为价格的配置节点按原值跟随，不据数值形态推断其业务用途；原非法价格／映射／结构判定不放宽，不承诺非法上游或全量立即通过。定向封面失败本件零保存，其他同步路径的封面失败语义不变。

每件保存后在同一事务中重新 SELECT，按实际金额格式或模型类型核对 `price`、`user_price`、`draft_premium`、`name`、`cover`、`description`、`config`、`draft_status`、`widget`、`stock`、`shared_stock`、`api_status`、`shared_sync` 13字段；核对对象来自同一次详情响应，不为验收再请求详情。只有事务成功返回才在 JSON 的 `verified_code_hashes` 中列入该哈希。首件失败即停剩余；两件逐件提交，第一件已成功、第二件失败时诚实返回 partial，不保证两件整体回滚，尤其不能把内存 SQLite 的回滚证据提升为生产表事务保证。

定向运行不推进普通 cursor、priority cursor、来源轮询或来源状态，安全摘要写入已有 runtime 下独立 `targeted-sync.log`，不混写普通 `sync.log`；后台普通同步记录不展示该定向日志。验收须同时核 JSON 状态、目标集合及 `verified_code_hashes`，不能只凭退出码或 planned 数。`--dry-run` 可读取目录，但不请求详情、下载封面、保存商品或标记 verified；它不能替代真实定向验收。

原请求重试与预算保持：最多一个逻辑目录、两个逻辑详情、两个不同封面，各可能最多3次物理 HTTP 尝试（总上界15，预算可能提前停止），同轮同图仍去重，不另发能力探测。部署、已保存完整跟随启用与真实商品写入应各处于明确授权内；关闭完整跟随或回退代码不会恢复已被覆盖／删除的本地配置。生产验收以固定制品和独立运维回执为准，不以本地合成通过替代。

### 周期图片刷新

周期同步只有在本件实际执行 `sync`、图片选择与单品「配置同步」同时有效时才刷新封面；`zero`、未选图片、单品门关闭及 dry-run 不下载图片。每次 `SyncService::run()` 开始一个新刷新轮次：同一规范绝对 URL 的周期刷新结果或非预算失败在本轮复用，跨商品、跨货源不重复刷新；下一轮重新 GET，因此上游同 URL 更换内容也能发现。预算中断不缓存：后续来源仍按自己的剩余预算尝试，不继承上一来源耗尽的配额。首次入库仍保留原有磁盘缓存／favicon 行为，既不读也不写周期刷新结果表；`full` 混合首次入库与既有商品同步时，同 URL 可能各有一次入库下载及周期刷新，仍受原总预算限制。

刷新使用既有 SafeHttpClient 的 HTTPS、公共地址、TLS、禁止重定向、绑定连接 IP、大小与位图校验，不信任 URL 扩展名。成功内容写到 `assets/cache/pika-supply-sync/<URL-SHA256>-<内容-SHA256>.<ext>`，校验与原子落盘完成后才保存商品引用；相同内容复用同一路径。新路径同时更新浏览器资源身份，不原位覆盖旧图，所以未选中但共用旧图的商品不会被连带改变。

远端空封面、HTTP 200 零字节图片、普通下载或图片校验失败时，只保留该商品原 `cover`，不会以 `/favicon.ico` 覆盖旧图，也不会再次请求本件详情或图片。其他字段继续经过原校验、六项选择及单品门处理；库存详情归零保护、规格／价格不匹配保护不变。图片未刷新仍计 `cover_failed`，本件计入 `failed`、来源为 `partial`；其他字段成功保存可同时计入 `applied.sync`，不代表图片成功。只选图片且失败时不保存任何商品字段；同件图片失败与规格待确认合并计一次 `failed`，各自细项仍保留。凭据／schema／响应大小／unknown 错误、预算和本地缓存完整性／落盘异常继续抛出，不能借“保留旧图”跳过安全错误。

“同 URL 一次刷新”不等于一次网络尝试：既有可重试传输／HTTP 错误最多 3 次，仍共用每源 120 秒、整轮 300 秒与原图片下载数／字节预算。新版内容文件及旧版本都计入原有 10000 文件／256MiB 缓存上限；不自动删除旧缓存、不做全缓存清理。下载在商品事务之前，后续商品保存失败可能留下未被引用的版本文件；回滚商品数据不会清除这些文件。CLI 摘要、缓存文件与真实浏览器解码是不同证据，成功数量不能代替逐图下载／渲染验收。

## 既有详情读取与安全边界

已有详情响应的结构摘要只保留有界整数业务码、data 和 type2 首分类 children／首商品位置的类型与实际数量；空数组／对象解码歧义明确保留，未观察字段不补造。

同步服务继续只读识别 CatalogHub 活动任务元数据，保留 basic/full 互斥，未重写同步引擎。单件隔离不包含价格/SKU 配置树或 INI 解析；这些异常仍停止。下面的最多 3 次是每次 HTTP 客户端调用的上限，不保证任意进程崩溃恢复后的累计次数。

三个已支持的精确只读详情端点将 MIME 标签用于兼容诊断，不再仅因标签不标准拒绝合法 JSON；仍须 HTTP 200、严格有界 JSON、协议业务成功与详情结构、原商品/价格/币种/内容安全校验。目录、图片、支付和其他请求不放宽，URL/TLS、公网 DNS/IP 固定、禁代理/跳转及大小/深度/节点/时间门不变。不从 HTML 提取或修补 JSON，不用旧目录补造商品，也不增加“不安全兼容”开关。

HTTPS 请求仍保持连接 5 秒、请求 90 秒、商品详情读取空闲 30 秒、目录读取空闲 60 秒、单货源 120 秒、整轮 300 秒及 systemd 外层 8 分钟边界。最多 3 次尝试（包含首次）只适用于可重试网络传输失败及 HTTP `408/429/502/503/504`，基础退避为 500／1000 毫秒。合法 `Retry-After` 仅在剩余预算容得下等待及下一次尝试时采用；预算不足即停，不保证发满 3 次。凭据、策略、业务码、JSON、结构、商品字段和预算错误不会自动重试，也不会输出原始上游错误。

智能货源中心隔离明确写库前单件错误：原有传输/可重试 HTTP 耗尽、未取得有效详情、纯商品字段错误，以及三个精确详情路径 HTTP 200/cURL 0 后真实 JSON 解码异常。该件不写入、不修补、不用目录补造，继续正常商品；原全量扫描相邻处理 5 件失败或当前未解决 100 件停止货源。显式固定补查清单最多 100 项，商品级异常不再阻断尚未补查项；不新增自动轮次。凭据、业务、解析成功后的结构/节点/大小、来源身份、全局配置、预算、本地缓存、数据库和检查点异常仍停止。JSON 错误仅保存成对数值码和固定类别；depth 表示本地深度 32 限制，旧记录无原因仍未记录。不增加自动 JSON 重试，不改变后续同步引擎。详见[失败分类与恢复](../../../docs/TROUBLESHOOTING.md#详情读取失败怎样处理)。

CatalogHub 的继续／只重试未入库项复用原任务和失败清单，processed/total 不倒退或重复累计；暂停不清除停止门。旧 `ITEM_DETAIL_RESPONSE_INVALID` 不全码放行，仅原可信 MIME 授权或准确当前 JSON 失败证据可取得原生继续资格，明确继续会重读当前未处理项一次。新版 schema 4 可读旧记录，旧版不能读新字段／失败码；发生新处理后禁止仅切旧源码或恢复旧 jobs，应保留最新状态、停止对账后兼容前向修复。以上不改变 basic/full 职责。

## 模式

- `basic`：只同步由 PikaSupplySync 自己导入的商品，不自动导入新商品。
- `full`：SupplySync 独立兼容模式；包含 `basic`，并自动发现新商品，按内部隔离根与远端分类导入。若该货源已由 CatalogHub 分类映射或活动任务管理，`full` 会在连接上游前拒绝运行，防止绕过已确认方案。

所有接入商品都会设置为允许 API 对接，使下游继续通过官方商户 ID 和密钥获取商品。
本扩展不会接管或修改任何既有商品的 `shared_sync`。只有本扩展新导入、带 `PKS1` 本地编号前缀的商品由周期同步管理；停用扩展不会让异次元原有商品失去官方同步。新商品按配置加价，默认 0%（不加价），使用者可自行设置所需比例。

周期库存规则与原生单品库存开关均允许时，缺货同步只把扩展管理的商品库存写为 0，不修改管理员设置的上下架状态。Pika 主题隐藏库存 0 商品；补货后成功写回正库存才恢复显示，关闭库存同步则保留本地库存。远端批量异常清零仍会触发熔断并保持上一轮库存。

清零保护的分母 D 仍为本站受管、允许库存同步且本地库存为正的商品数（不以手工上下架状态筛选）。E 为其中目录明确返回合法零库存的商品数，M 为目录缺项数。明确零库存独立使用 `E >= zero_fuse_min` 且 `100 * E / D > zero_fuse_percent` 的保护门；缺项继续使用原 E+M 总量门。默认仍为至少 5 件且严格超过 10%，比例刚好相等不触发。缺项触发总量门时保留库存，未触发仍按既有规则清零；缺项原因未知，不代表永久下架。日志的 `mass_zero_fuse/ratio` 仍表示总量门，因此总量熔断时，未触发独立门的明确零库存仍可按原批量和游标同步；定向 CLI 的全源保护不放宽。

普通目录的库存字段缺失、null 或不符合既有校验时，本货源本轮在规划前拒绝商品写入，不再默认成 0；合法整数、数字字符串及整数浮点兼容不变。CatalogHub 普通目录分析复用该入口，同样拒绝不完整库存。镜像严格库存校验、V4 既有无库存字段兼容、正常补货、单品开关、时间预算与目录正库存／详情零库存的竞态保护均不改变。目录仍是快照，阈值以下误报零的风险不能由此消除。

## 首次使用

1. 保存并启动 `PikaCatalogHub` 与 `PikaSupplySync`，在「智能货源中心」使用「测试并接入」添加上游。该动作会自动写入异次元原生共享店铺表，不要再到原生页面重复添加或点击「接入货源」。
2. 完成分析：默认智能分类检查「平台 → 可选系列 → 货源别名 → 上游原始分类」；显式镜像则核对源站完整路径和分类 ID，不插入后台别名层。确认分类及加价后才入库；公开默认加价为 `0%`。
3. 在 LocalExtensions 管理页把同步模式设为 `basic`，填写需要限制的货源 ID、批次上限和后续新品默认加价。
4. 启用 `PikaSupplySync`，再执行预览：

```bash
php local-extensions/extensions/PikaSupplySync/bin/sync.php --dry-run
```

5. 确认摘要后执行：

```bash
php local-extensions/extensions/PikaSupplySync/bin/sync.php
```

服务器定时器只需要调用上述 CLI；扩展停用后 CLI 会从独立的 LocalExtensions 状态中读取到停用状态并拒绝运行。

只有未安装 `PikaCatalogHub`、明确单独使用 SupplySync 的兼容场景，才需要先在异次元原生页面建立 `shared` 记录；这不是整套 Acg-Faka Extensions 的推荐流程。原生「接入货源」会直接批量创建商品，没有 CatalogHub 的分类确认和后台任务控制。

## 安全行为

- 每个货源同一时间只允许一个任务。
- 运行时只连接 HTTPS 标准 443 的公共网络根地址；含凭据、参数、私网或保留地址的货源会被拒绝。
- 所有接口请求启用 TLS 证书验证、禁止重定向，并把已验证的公共 DNS 地址绑定到实际连接；实际连接 IP 不一致时拒绝响应。
- 上游 HTTPS 的连接超时为 5 秒，单次请求最长 90 秒；大型商品目录 JSON 的读取空闲上限为 60 秒，其他 JSON 与图片仍为 30 秒。每个货源在一轮同步中最多使用 120 秒，整轮同步最多使用 300 秒。最多三次的请求尝试不会重置这些预算：每次重试前都会按货源与整轮的剩余时间缩短连接和请求超时，预算耗尽后不再发起下一次请求。
- 商品封面只从公共 HTTPS 下载并保存为本站静态图片，买家页面不会加载上游控制的图片地址；商品说明中的远程图片会被移除。
- 单轮最多下载 100 张、合计 50MB 封面，累计商品文本最多 10MB；上述应用内时间预算会在可检查边界执行，但系统 DNS 查询无法由 PHP 预算抢占，因此这不是进程硬截止。systemd 模板另设 8 分钟外层上限；真实 unit 的截止行为仍须在 目标站点验证。封面缓存达到 10000 文件或 256MB 后停止新增。
- 远端控件正则只接受不含分组、分支、回溯引用且最多一个可变量词的安全子集；安全表达式缺少首尾锚点时会补为完整匹配，危险表达式仍会拒绝。
- 远端连接失败或返回空目录时不执行下架。
- 单次大量商品突然清零时触发熔断，相关商品不写入。
- 单货源 batch 是每轮处理上限，不保证满额完成、覆盖同等数量的唯一商品或产生同等数量的写入。来源结果 `status`、`applied`、`failed` 的原含义保持，诊断不覆盖这些结果；`partial` 可能已有成功提交的动作，后续失败不会自动撤销，不能把非零退出码解释为全轮零写入。
- 批次最多使用 75% 容量处理库存差异，保留其余容量轮询普通价格与配置，持续竞态不会永久占满批次。
- 既有商品的价格、配置与库存同步开关保持原值；关闭的字段不会被插件覆盖。
- 扩展不修改商品 `status`，管理员手工上架或下架状态始终保持不变。
- `--dry-run` 只读取目录并输出计划，不改商品和游标。
- dry-run 或同步摘要中的货源状态为 `locked` 或 `held_empty_catalog` 时不算同步验收通过：前者表示本轮未取得该货源的同步锁，后者表示安全门拦截了异常空目录；必须排除占用或确认已认证上游恢复合理的非空目录后，才可在准确授权及轮数／时长上限内重新验收。其他外部重跑也遵循该边界，不能自行无限继续。
- 扩展只记录有界摘要；安全诊断可包含固定类别及有界 HTTP/cURL 数值、耗时和实际尝试数，未采集值不等于测量为零。不记录上游错误原文、响应正文/头、上游地址或商户密钥。
